# 从理解到独立交付的实践里程碑

当前 NPU 平台未选择。前期使用小张量和 CPU/PyTorch；进入设备实践后固定芯片、SDK、编译器和运行时。没有运行过的设备项目只能标记“待验证”。

## 验收路径

| 阶段 | 交付物 | 验收重点 |
| --- | --- | --- |
| P01 参考 Block | 手写小型 Decoder Block、形状注释与测试 | 对齐 Attention、归一化、FFN 和残差输出 |
| P02 生成循环 | 自己编写 Prefill/Decode、KV Cache 和采样 | 对照无缓存参考，检查位置、掩码、状态和停止条件 |
| P03 模型复现 | 加载一个小规模公开检查点，复现 forward | tokenizer、权重映射、逐层输出与 logits 对齐 |
| P04 NPU 基础算子 | elementwise、归约、softmax、归一化、RoPE、GEMM | 覆盖形状、尾块、精度和重复运行 |
| P05 结构算子 | Attention、缓存，以及 MoE/递归状态更新 | 与独立参考对齐，多请求状态互不污染 |
| P06 整模型 NPU 基线 | 权重准备、图适配、注册、执行和生成入口 | 从输入文本到输出文本，记录实际执行设备及回退 |
| P07 端到端优化 | 基线、瓶颈、逐项优化、消融和回归报告 | 同工作负载下比较质量、延迟、吞吐、内存 |
| P08 陌生模型适配 | 独立完成未精读模型的结构拆解与适配 | 分析新机制对算子、状态、运行时和资源的影响 |

## 从零开发的范围

能够独立实现必要的参考计算、核心算子和执行循环，也能够选择经过验证的库。学习编译器/驱动/运行时接口，不要求重造完整操作系统或编译器。

大模型可先用保持机制的小配置实验，但必须标为缩小实验，不能代替原始模型的完整容量、精度和性能验收。

## 每次实验需要的证据

- 模型、权重和代码版本，芯片、工具链、输入形状、dtype、layout、随机种子及复现命令。
- 单算子与逐层对照，绝对/相对误差及任务质量指标；根据数值精度和机制选择阈值。
- 状态初始化、追加、复用、拒绝回滚和清空，覆盖变长、多轮、多请求与边界输入。
- 区分编译、加载、预热和稳态；设备计时包含必要同步。记录输入/输出长度、并发和重复次数。
- TTFT、逐 token 延迟、吞吐、峰值内存及通信开销；区分单 kernel 收益和整模型收益。

先建立正确基线，再根据 profiler 做单变量实验。量化、裁剪、稀疏化或近似状态处理单独记录质量变化，不只看速度。

## 理论与实践分别记录

每个主题分别记录“能解释”“能实现 CPU 参考”“已通过目标 NPU 验证”“已完成性能优化”。“吃透了”可以完成理论归档；“跳过”保留摘要，均不自动产生设备验证证据。

建议每日完成小练习，并另留完整时段进行阶段项目。复杂算子、模型迁移和调优可以跨多天。
