## 定义与处理流程

Tokenizer 将文字变为模型可使用的 ID。常见处理框架为：按配置规范化文字 → 预切分 → 分词模型（如 BPE）及词表映射 → 后处理。之后才进入神经网络的 Embedding。各步骤是否执行、怎样执行，由具体配置决定；文本规范化与处理隐藏向量的 RMSNorm 不同。[官方流程](https://huggingface.co/docs/tokenizers/pipeline)

BPE 通过逐轮合并高频的相邻单位学习词表和合并规则。本课从字符开始，字节级 BPE 则使用字节作为基础单位；二者不能简单等同于“按汉字切分”。[BPE 官方课程](https://huggingface.co/learn/llm-course/en/chapter6/5)

## 训练时统计当前相邻对

教学语料为 `abab` 出现 4 次、`abac` 出现 2 次、`ac` 出现 1 次。初始词表 `{a:0,b:1,c:2}`；每个字符串独立处理，不跨片段合并、不做规范化、不加特殊 token，达到 V=6 后停止。

| 轮次 | 当前相邻对的加权计数 | 合并及新增 ID |
| --- | --- | --- |
| 1 | `(a,b)=10`，`(b,a)=6`，`(a,c)=3` | `a+b→ab`，ID 3 |
| 2 | `(ab,ab)=4`，`(ab,a)=2`，`(a,c)=3` | `ab+ab→abab`，ID 4 |
| 3 | `(ab,a)=2`，`(a,c)=3` | `a+c→ac`，ID 5 |

第一轮 `(a,b)` 的计数是 `2×4 + 1×2 + 0×1 = 10`。计数对象是**当前相邻 token 对**，合并后必须重新统计。第一轮全是单字符，才恰好等同于统计原文的 `ab` 子串；`abab` 成为单个 token 后，内部不再有相邻 token 对。原有 token 留在词表中。[算法依据：原论文 §3.2](https://aclanthology.org/P16-1162.pdf)

## 使用时应用已确定的规则

最终词表为 `{a:0,b:1,c:2,ab:3,abab:4,ac:5}`。普通确定性编码按训练得到的合并优先级工作，不根据新输入的频次重新训练。

```text
新片段 ababac
初始：a / b / a / b / a / c
规则 1 后：ab / ab / a / c
规则 2 后：abab / a / c
规则 3 后：abab / ac
ID：[4,5]；S=2，V=6；B=1 时 ID 张量形状为 [1,2]
```

即使新输入里 `ac` 出现 100 次，也不会把第三条规则改为第一条。这一区别是“学习规则”和“应用规则”；分词器训练本身也不是更新 Transformer 权重。[训练与编码算法](https://huggingface.co/learn/llm-course/en/chapter6/5)

## 复习与适用边界

- 能解释 tokenizer 在查表之前还需要决定切分边界。
- 能按语料频次计算当前相邻对，并说明为何不能沿用旧计数。
- 能按既定规则编码新片段，计算 ID、S、V；规则无匹配时不执行合并。
- 高频片段不必是完整单词，也不保证有独立词义。真实 tokenizer 还涉及预切分、字节、特殊 token 等，不能将此例当作完整兼容实现。
